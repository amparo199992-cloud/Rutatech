## Tu portafolio: la prueba de lo que sabes hacer

Para un primer empleo en tecnología, tu portafolio pesa tanto o más que tus títulos. Es la evidencia de que **sabes construir cosas**.

### Calidad antes que cantidad

Tres proyectos bien hechos valen más que quince tutoriales copiados. Un buen proyecto de portafolio:

- **Resuelve un problema real** (aunque sea pequeño): un control de gastos, una app para tu comunidad, un análisis de datos de tu ciudad.
- **Es tuyo:** si partiste de un tutorial, agrégale funciones propias y explica qué cambiaste.
- **Funciona y se puede ver:** tiene un enlace de demostración en vivo o capturas y un video corto.
- **Está bien documentado:** un README claro (lo verás en el último módulo).

### Estructura de tu sitio de portafolio

1. **Inicio:** tu nombre, el rol que buscas ("Desarrolladora web junior") y una frase sobre lo que te mueve.
2. **Proyectos:** 3 a 6, cada uno con imagen, descripción breve, tecnologías, enlace al código y a la demo.
3. **Sobre mí:** tu historia en pocas líneas. Si vienes de otra carrera, ¡es una fortaleza! Cuenta cómo te ayuda.
4. **Habilidades:** solo las que realmente puedes usar.
5. **Contacto:** correo profesional, LinkedIn y GitHub.

### Cómo presentar cada proyecto

Usa el formato **Problema → Solución → Resultado**:

> **Control de Gastos Familiar.** Mi familia anotaba los gastos en papel y no sabía en qué se iba el dinero. Construí una app web con Python y SQLite que registra gastos por categoría y genera un resumen mensual. La usamos desde marzo y redujimos un 15 % los gastos en domicilios.

### Dónde publicarlo

- **GitHub Pages**, **Netlify** o **Vercel** publican sitios estáticos gratis.
- Puedes usar un dominio propio (`tunombre.dev`) o el subdominio gratuito del servicio.

### Errores comunes

- Enlaces rotos o demos que ya no funcionan. Revísalos cada mes.
- Demasiadas animaciones que hacen lento el sitio.
- Faltas de ortografía. Pide a alguien que lo lea.
- No adaptarlo a celular: muchas personas de selección lo abren desde el teléfono.

> 💡 **Idea clave:** tu portafolio también es un proyecto. Hazlo responsive, accesible y rápido: demuestra lo que aprendiste en la etapa 4.

## GitHub y LinkedIn: tu vitrina profesional

### Optimiza tu perfil de GitHub

1. **Foto y nombre reales**, y una biografía corta: "Estudiante de desarrollo web | Python y JavaScript | Bogotá".
2. **README de perfil:** crea un repositorio con **exactamente tu nombre de usuario**. Su README aparece en tu página principal. Incluye quién eres, qué estás aprendiendo, tus proyectos destacados y cómo contactarte.
3. **Fija tus mejores repositorios** (hasta 6) con la opción *Customize your pins*.
4. Cada repositorio con **descripción, temas (topics) y README**.
5. **Commits constantes** con buenos mensajes. No se trata de llenar el calendario de cuadros verdes, sino de mostrar trabajo real.

```markdown
# Hola, soy Andrea 👋

Estudio desarrollo web y me apasiona crear herramientas útiles para mi comunidad.

- 🔭 Estoy construyendo: un directorio de emprendimientos locales
- 🌱 Aprendiendo: React y PostgreSQL
- 📫 Contacto: andrea.dev@correo.com · [LinkedIn](https://www.linkedin.com/in/tu-perfil)

### Proyectos destacados
- [Control de gastos](https://github.com/andrea-dev/control-gastos): Python + SQLite
```

### Optimiza tu perfil de LinkedIn

- **Titular:** no solo "Estudiante". Mejor: "Desarrollador web junior | JavaScript, React, SQL | Busco mi primera oportunidad".
- **Acerca de:** 3 o 4 párrafos cortos: quién eres, qué sabes hacer, qué buscas y una prueba (enlace a tu portafolio).
- **Experiencia:** incluye proyectos, voluntariados y trabajos previos. Habilidades como atención al cliente, liderazgo o gestión son valiosas en tecnología.
- **Sección Destacados:** enlaza tu portafolio y tus mejores proyectos.
- **Habilidades y certificaciones:** agrega las que puedas demostrar.
- **URL personalizada:** `linkedin.com/in/tu-nombre`.

### Haz visible tu aprendizaje

Publica de vez en cuando lo que aprendes: "Esta semana construí X y aprendí Y". Comenta con aportes en publicaciones de otras personas del sector. Muchas oportunidades llegan por la red de contactos, no por las ofertas publicadas.

### Activa la opción "Open to Work"

LinkedIn permite indicar que buscas empleo, ya sea visible para todo el mundo o solo para reclutadores.

> 💡 **Idea clave:** que tu GitHub, LinkedIn, CV y portafolio cuenten **la misma historia**, con los mismos proyectos y el mismo rol objetivo.

## Tu CV técnico

Un reclutador dedica pocos segundos a la primera lectura de un CV. El tuyo debe ser **claro, breve y orientado a resultados**.

### Estructura recomendada (una página)

1. **Encabezado:** nombre, rol objetivo, ciudad, correo, teléfono, LinkedIn, GitHub y portafolio.
2. **Perfil:** 2 o 3 líneas con quién eres y qué aportas.
3. **Habilidades técnicas:** agrupadas (Lenguajes: Python, JavaScript · Bases de datos: SQL, PostgreSQL · Herramientas: Git, VS Code).
4. **Proyectos:** para perfiles junior, esta sección va **antes** de la experiencia.
5. **Experiencia:** incluso si no es de tecnología; destaca lo transferible.
6. **Educación y certificaciones.**
7. **Idiomas:** indica tu nivel real de inglés.

### Describe logros, no tareas

Usa la fórmula **verbo de acción + qué hiciste + resultado o tecnología**:

| ❌ Débil | ✅ Fuerte |
|---|---|
| Hice una página web | Desarrollé una app web responsive con React y Express que permite registrar gastos por categoría |
| Ayudaba con computadores | Resolví más de 30 solicitudes de soporte mensuales, reduciendo el tiempo de respuesta con una guía de autoservicio |
| Sé Python | Automaticé con Python la generación de un informe semanal, ahorrando 3 horas de trabajo manual |

### Sistemas de seguimiento de candidatos (ATS)

Muchas empresas filtran los CV con software antes de que los lea una persona. Para pasarlos:

- Usa un formato **simple**: una columna, sin tablas complejas ni texto dentro de imágenes.
- Incluye las **palabras clave** de la oferta que de verdad tienes (si piden "SQL" y lo sabes, escríbelo así).
- Envíalo en **PDF**, salvo que pidan otro formato, con un nombre como `CV-Ana-Gomez-Desarrolladora.pdf`.

### Adáptalo a cada oferta

Ten un CV base y ajusta el perfil, el orden de las habilidades y los proyectos según cada vacante. Diez CV adaptados funcionan mejor que cien genéricos.

### Lo que no debes incluir

- Información que no guarda relación con el trabajo y puede generar sesgos (estado civil, religión, número de documento). En algunos países se acostumbra poner foto; si no la piden, no es obligatoria.
- Habilidades que no puedes demostrar en una entrevista.
- Barras de "nivel de habilidad" (por ejemplo, Python ★★★★☆): no informan nada concreto.

> 💡 **Idea clave:** si escribes una tecnología en tu CV, debes poder hablar de un proyecto donde la usaste.

## Prepara tus entrevistas técnicas

Un proceso típico para un rol junior tiene varias etapas: entrevista inicial con recursos humanos, una prueba técnica (en casa o en vivo), una entrevista técnica con el equipo y, a veces, una entrevista final.

### Entrevista de comportamiento: el método STAR

Para preguntas como "Cuéntame de un problema difícil que resolviste", responde con **STAR**:

- **S**ituación: el contexto.
- **T**area: qué tenías que lograr.
- **A**cción: qué hiciste **tú** (en primera persona).
- **R**esultado: qué pasó y qué aprendiste.

Prepara 4 o 5 historias que puedas adaptar: un reto técnico, un error del que aprendiste, un conflicto en equipo, algo que aprendiste rápido.

### Preguntas técnicas frecuentes para junior

- ¿Qué pasa cuando escribes una URL en el navegador? *(Etapa 1)*
- ¿Diferencia entre una lista y un diccionario? *(Etapa 2)*
- ¿Qué es la complejidad O(n)? *(Etapa 3)*
- ¿Qué es el DOM? ¿Diferencia entre `let` y `const`? *(Etapa 4)*
- ¿Qué es un JOIN? ¿Qué es una clave primaria?
- Explícame uno de tus proyectos: ¿por qué elegiste esas tecnologías? ¿qué cambiarías?

### Ejercicios de programación en vivo

No esperan perfección: evalúan **cómo piensas**. Sigue estos pasos:

1. **Repite el problema** con tus palabras y haz preguntas: ¿la lista puede estar vacía? ¿hay números negativos?
2. **Piensa en voz alta** y propone un ejemplo.
3. Empieza con una solución **sencilla que funcione**, aunque no sea la más eficiente.
4. **Prueba** tu código con casos normales y extremos.
5. Si te bloqueas, dilo y explica qué estás pensando. Pedir una pista es válido.

Practica en plataformas como **Exercism**, **freeCodeCamp** o **LeetCode** (problemas fáciles), y con los retos de RutaTech.

### Preguntas que tú debes hacer

Al final siempre te preguntarán si tienes dudas. Ten preparadas algunas:

- ¿Cómo es un día típico en el equipo?
- ¿Cómo apoyan el aprendizaje de las personas junior? ¿Hay mentorías?
- ¿Qué esperan que logre en los primeros tres meses?

### Si no sabes algo

Di la verdad: "No lo he usado, pero sé que sirve para X y lo aprendería así…". La honestidad y la capacidad de aprender valen más que fingir.

> 💡 **Idea clave:** cada entrevista es práctica. Después de cada una anota qué te preguntaron y qué te costó; eso es tu siguiente plan de estudio.

## Documenta tus proyectos como profesional

Un proyecto sin documentación es un proyecto que nadie (ni tú en seis meses) entiende. El **README.md** es la primera impresión de tu trabajo.

### Plantilla de README

```markdown
# Control de Gastos 💰

Aplicación web para registrar gastos por categoría y ver un resumen mensual.

🔗 Demo: https://control-gastos.netlify.app

![Captura de la pantalla principal](docs/captura.png)

## Funcionalidades
- Registro, edición y eliminación de gastos
- Resumen por categoría con gráfico
- Exportación a CSV

## Tecnologías
Python · Flask · SQLite · HTML · CSS

## Cómo ejecutarlo localmente
1. Clona el repositorio:
   git clone https://github.com/usuario/control-gastos.git
2. Crea y activa un entorno virtual:
   python -m venv .venv
3. Instala las dependencias:
   pip install -r requirements.txt
4. Ejecuta:
   python app.py

## Lo que aprendí
- Diseñar tablas relacionadas en SQLite
- Validar formularios en el servidor

## Próximas mejoras
- Autenticación de usuarios
- Modo oscuro

## Autor
Ana Gómez · [LinkedIn](https://www.linkedin.com/in/tu-perfil)
```

### Claves de un buen README

- **Qué es y para qué sirve**, en la primera línea.
- **Captura o GIF**: muestra el proyecto sin obligar a instalarlo.
- **Instrucciones que funcionen**: pruébalas en un equipo limpio o pídele a alguien que las siga.
- **"Lo que aprendí"**: a los reclutadores les encanta ver tu proceso de pensamiento.

### Documentar el código

- Usa **nombres claros** de variables y funciones: el mejor comentario es el que no hace falta.
- Comenta el **por qué**, no el qué:

```python
# ❌ Suma 1 a i
i += 1

# ✅ Los meses empiezan en 0 en la API, pero mostramos del 1 al 12
mes_visible = mes_api + 1
```

- Escribe **docstrings** en funciones importantes.

### Otros archivos útiles

- `.gitignore`: lo que no se sube.
- `LICENSE`: indica cómo pueden usar tu código otras personas (MIT es una licencia sencilla y popular).
- `.env.example`: lista las variables de entorno necesarias, **sin valores reales**.
- `CHANGELOG.md`: registro de cambios por versión (en proyectos más grandes).

> 💡 **Idea clave:** antes de enviar tu portafolio, abre cada repositorio como si fueras un reclutador con dos minutos: ¿se entiende qué es, cómo se ve y qué aprendiste?
